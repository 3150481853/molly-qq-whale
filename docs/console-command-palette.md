# 控制台「查找功能」（命令面板）升级 — 2026-11-05

## 为什么改

主人原话：控制台功能太多，找起来不友好。旧面板只能跳到 15 个页面，写着「回车打开第一项」，
进去还得自己翻卡片找按钮。这次把它变成「页面导航 + 一句话执行」：搜到的动作直接跑，
不用先想它在哪一页。

## 交互

| 操作 | 行为 |
| --- | --- |
| `Ctrl+K` / 点侧栏「查找功能」 | 打开面板 |
| 输入 | 按名称、描述、同义词、分类实时过滤（前缀命中优先级最高） |
| `↑` `↓` | 上下选择（循环） |
| `Enter` | 打开选中的页面，或执行选中的动作 |
| `Esc` / 点遮罩 | 关闭 |

结果按段分组，一次只出现一次标题：

- `页面` — 15 个页面，右侧提示「打开 ↗」
- `执行 · QQ` / `执行 · 守护` / `执行 · 插件` … — 动作，绿色 `▶`，右侧提示「执行 ↵」

## 动作怎么执行（没有第二套写入通路）

挑中动作时不会在面板里直接拼请求，而是：

1. 跳到「高级操作」（`#/exec`）；
2. 找到那张动作卡，滚动到视口中间并高亮 1.8 秒；
3. 调用卡片自己的 `executeCard()` —— 字段校验、危险动作的系统确认弹窗、
   结果输出区（stdout / data / 二维码）全部沿用同一份代码。

这样面板里点「改写守护配置」仍然会要求填 patch 并二次确认，不会因为图快绕开保护。

## 代码落点

- `console/console.js`
  - `commandEntries()`：把 `FEATURE_LINKS`（页面）与 `ACTIONS`（动作）拼成同一份索引。
  - `commandScore()`：`名称前缀 100 / 名称包含 60 / 分类命中 30 / 全文 20`。
  - `renderCommandResults()`：按段分组、最多 24 条，段内按得分排。
  - `commandSetActive()` / `commandChoose()` / `runActionFromPalette()`。
  - `bindCommandPalette()`：键盘（`Ctrl+K`、`↑↓`、`Enter`、`Esc`）与结果区点击委托，
    统一走 `preventDefault()` 后自行处理，避免 `<a href>` 与面板逻辑重复触发。
- `console/index.html`：底部提示改成「输入名称或用途查找功能 · ↑↓ 选择 · 回车打开或执行」。
- `console/console.css` §35：分组标题、动作行图标/文字配色、`exec` 卡片 `is-flash` 高亮。

## 验收（2026-11-05 12:40，桌面壳 + CDP 实测）

- 默认列表 24 条；查询 `QQ` → 6 条，分组 `页面 / 执行 · QQ / 执行 · 进程 / 执行 · 插件`（无重复标题）。
- 查询 `守护` → 7 条，`守护状态` 排第一（名称前缀命中）。
- `Enter` 选中「守护状态」→ 跳到 `#/exec`、执行完成：结果区 `成功 278 ms HTTP 200`。
- 点「关于」→ `location.hash` 变 `#/about`，面板关闭。
- `Esc` 关闭面板；`↑↓` 在 6 条结果中正确移动（down→1、up→0）。
- `node --check console.js` 退出 0；`console.css` 花括号 861/861。

## 已知限制

- 需要填字段的动作（改写守护配置）跳到卡片后仍要手填——面板只负责「带你去那张卡并按下按钮」。
- 面板不做历史记录/最近使用排序（当前按名称与分类打分），后续需要再加。
